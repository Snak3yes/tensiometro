## Comunicação Entre Componentes

### Padrão: Signals/Slots do Qt

```
┌──────────────────────┐         signal         ┌──────────────────────┐
│  ConnectionManager   │ ──────────────────────>│  AOIControllerApp    │
│                      │   plc_connected()      │                      │
│                      │                        │  _on_plc_connected() │
└──────────────────────┘                        └──────────────────────┘
       ▲                                                   ▲
       │                                                   │
       │ connect PLC                                       │ update UI
       │                                                   │
┌─────┴───────────────────────────────────────────────────┴─────┐
│                                                                 │
│                    CNCControlTab                               │
│  • connect_btn.clicked  →  ConnectionManager.connect_plc()     │
│  • status_updated        →  ConnectionManager status signal   │
│  • position_updated      →  Controller callback               │
└─────────────────────────────────────────────────────────────────┘
```

### Exemplo de Interação

```
USUÁRIO clica em "Conectar PLC"
    │
    ▼
CNCControlTab.connect_btn.clicked
    │
    ├─> ConnectionManager.connect_plc()
    │       │
    │       ├─> controller.cnc.connect()
    │       │       │
    │       │       └─> PLC (Modbus TCP)
    │       │
    │       ├─> Sucesso? plz emit('plc_connected')
    │       │
    │       └─> Erro? plz emit('plc_connection_error')
    │
    └─> plz connect(ConnectionManager.plc_connected,
                    AOIControllerApp._on_plc_connected)
            │
            └─> Atualiza UI: "Conectado"
                • Atualiza status label
                • Habilita controles de movimento
                • Inicia timer de posição
```

## Responsabilidades Claras

### AOIControllerApp (MainWindow)
```
✅ ORQUESTRAR abas e menus
✅ INICIALIZAR managers
✅ CONECTAR signals/slots
✅ GERENCIAR estado global

❌ NÃO implementa lógica de negócio
❌ NÃO conhece detalhes de hardware
❌ NÃO tem UI direta (só orquestra)
```

### Managers
```
✅ LÓGICA DE NEGÓCIO pura
✅ SEM dependências de PyQt widgets (exceto signals)
✅ TESTÁVEIS sem UI

❌ NÃO implementam UI
❌ NÃO acessam diretamente widgets
```

### Tabs
```
✅ LAYOUT e UI específica
✅ DELEGAM negócio para managers
✅ RECEBEM events e atualizam display

❌ NÃO têm lógica de negócio complexa
❌ NÃO acessam hardware diretamente
```

### Dialogs
```
✅ COLETAR dados do usuário
✅ VALIDAR entrada
✅ RETORNAR dados estruturados

❌ NÃO executam ações (apenas coletam dados)
```

## Vantagens da Nova Estrutura

### 1. MANUTENIBILIDADE
```
Antes: "Onde está o código de conexão PLC?"
Resposta: "Em algum lugar dos 4k linhas da main window"

Depois: "Onde está o código de conexão PLC?"
Resposta: "Em managers/connection_manager.py"
```

### 2. TESTABILIDADE
```
Antes: Como testar connect_cnc()?
❌ Precisa instanciar MainWindow inteira
❌ Precisa PyQt6 rodando
❌ Precisa todos os widgets

Depois: Como testar ConnectionManager.connect_plc()?
✅ Apenas instancia manager
✅ Mock de controller
✅ Teste unitário simples
```

### 3. COLABORAÇÃO
```
Cenário: 2 devs trabalhando

Antes:
🔴 Dev A edita consumo_lib.py (linhas 1-3000)
🔴 Dev B edita consumo_lib.py (linhas 3000-6000)
🔴 Merge conflict QUASE garantido

Depois:
✅ Dev A edita managers/connection_manager.py
✅ Dev B edita tabs/inspection_tab.py
✅ Zero conflitos
```
